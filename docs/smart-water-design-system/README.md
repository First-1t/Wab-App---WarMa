# Smart Water — Color Tokens

พาเลตสีสำหรับเว็บแอป **Smart Water** (EN813701 WAD26-02) — ระบบแนะนำการให้น้ำมันสำปะหลัง เป็น **ไลท์ธีมเดียว** ตามที่ขอ ยึดแนวคิดเดิมของทีมไว้ครบ: **เขียว = พืช/การเกษตร** และ **ฟ้า = น้ำ** โดยทั้งสองเป็นสีแบรนด์คู่กัน (ดูหัวข้อ "บทบาทของเขียวกับฟ้า" ด้านล่าง) เพียงแต่ปรับค่าจริงให้ทุกคู่สีผ่านมาตรฐาน WCAG AA

## ที่มา — แก้ 2 จุดจากพาเลตที่ทีมส่งมาให้ดูก่อนหน้า
1. สองรหัสของ "Primary" เดิม (#439A86 กับ #65B741) เป็นคนละเฉด (teal หม่น กับ lime สด) ไม่ใช่สีเดียวกันคนละน้ำหนัก — ระบบนี้เหลือ Primary เฉดเดียวที่แน่นอน
2. ตัวอักษรสีขาวบนปุ่มเขียว/ฟ้าเดิม แทบทุกคู่คอนทราสต์ไม่ผ่าน (2.0–3.4:1) — พาเลตนี้ปรับความเข้มของสีให้ตัวอักษรขาวใช้ได้จริงกับทุกปุ่ม

## Action colors
`secondary`, `success`, `warning`, `danger` — ทั้ง 4 สีนี้ใช้กับ **ตัวอักษรขาวขนาดปกติได้ทันที** ผ่าน WCAG AA (≥4.5:1): secondary 5.0:1, success 5.0:1, warning 5.0:1, danger 6.5:1

`primary` เปลี่ยนเป็นเขียวสดตามที่ทีมขอ (#65B741) — **สว่างเกินกว่าตัวอักษรขาวจะอ่านออก (2.5:1) ต้องใช้ตัวอักษรเข้ม (`text`) แทนเสมอ (5.87:1)** ต่างจาก 4 สีข้างต้น ห้ามใส่ตัวอักษรขาวบนปุ่ม primary เด็ดขาด `primary-hover` (#5FA33E) ก็ยังต้องคู่กับตัวอักษรเข้มเช่นกัน (4.74:1) ส่วน `secondary-hover` ยังคู่กับตัวอักษรขาวได้ตามปกติ

## บทบาทของเขียวกับฟ้า
ทั้งสองสีเป็นสีแบรนด์ แต่แบ่งหน้าที่ชัดเจน เพื่อให้ผู้ใช้รู้ทันทีว่าปุ่มไหนคือปุ่มหลักของหน้า:

| สี | token | ใช้กับ |
|---|---|---|
| **เขียว** | `primary` / `primary-hover` | ปุ่ม action หลักของหน้า (เช่น "ดูคำแนะนำ", "ถัดไป") — **หน้าละ 1 ปุ่มทึบ** ตัวอักษรเข้มเสมอ |
| **ฟ้า** | `brand` / `brand-hover` | Navbar, ลิงก์, ปุ่ม outline — ตัวอักษรขาวบนพื้นฟ้า / ตัวอักษรฟ้าบนพื้นอ่อน |
| ฟ้า | `secondary` / `secondary-hover` | ปุ่มรองแบบทึบ และเส้นกราฟข้อมูลน้ำ |

กฎที่ต้องจำ 3 ข้อเมื่อสองสีอยู่ด้วยกัน:
1. ถ้าวางปุ่มเขียวคู่กับปุ่มฟ้า ให้ใช้ปุ่มฟ้าแบบ `.btn-outline` ไม่ใช่แบบทึบ ไม่งั้นสองสีทึบจะแย่งกันเป็นปุ่มหลัก และตัวอักษรบนปุ่มจะสลับขาว/เข้มไปมาจนดูไม่เป็นชุดเดียวกัน
2. ห้ามใช้เขียวเป็นเส้นหรือไอคอนบางๆ บนพื้นฟ้า (1.98:1 ต่ำกว่า 3:1)
3. `brand` ตอนนี้เป็นเลข hex เดียวกับ `secondary` (#1D74B8) แต่แยก token ไว้ให้ปรับแยกกันได้ในอนาคต ถ้าเปลี่ยนค่าใดค่าหนึ่งให้เช็คคอนทราสต์ใหม่ทั้งคู่

## Components
มี 6 component แล้ว: `Button` (primary/secondary/outline × lg/sm), `Field` (label+input+error), `Card` (กล่อง step ของ wizard), `Badge` (success/warning/danger — ตรงกับผล matched/low-confidence/no-match ของ matching engine พอดี), `Navbar` (แถบเมนูฟ้า) และ `Link` (ลิงก์ฟ้าขีดเส้นใต้) CSS รวมอยู่ไฟล์เดียวที่ `components/bundle.css` แต่ละตัวมี README ของตัวเองในโฟลเดอร์ ยังไม่มี: disabled button, ปุ่มไอคอนอย่างเดียว, select/checkbox/radio, ตัวแสดงความคืบหน้าข้าม step, เมนูพับสำหรับมือถือ

## Neutral & background
`surface` (ขาว — การ์ด/พาเนล), `surface-sunken` (พื้นหลังหน้าเว็บ โทนมินต์อ่อนมาก), `text` (13.8:1 บน surface-sunken — AAA), `text-muted` (5.8:1 — AA), `border` (เส้นแบ่ง/ขอบ input ไม่มีข้อกำหนดคอนทราสต์เพราะไม่ใช่ตัวอักษร)

## Tint (ตกแต่ง)
`tint-mint`, `tint-sky` — เก็บโทนพาสเทลเดิม (Mint Green / Ice Blue) ที่ทีมชอบไว้ ใช้เป็นพื้นหลัง badge/chip หรือพื้นที่กราฟเท่านั้น **จับคู่กับ `text` เสมอ ห้ามใช้กับตัวอักษรขาว** เพราะเป็นโทนอ่อนคอนทราสต์ต่ำ และบน `tint-sky` ห้ามใช้ตัวอักษรสี `brand` (เหลือ 4.16:1 ไม่ผ่าน AA) ให้ใช้ `brand-hover` (6.11:1) หรือ `text` แทน

## ข้อควรระวัง: success กับ danger
`success` (เขียว) และ `danger` (แดง) เป็นคู่สีที่คนตาบอดสีแดง-เขียวแยกยากที่สุด และในระบบนี้คู่นี้ตรงกับฟีเจอร์จริง — "พบ scenario ที่ตรง" กับ "ไม่พบข้อมูลที่ตรง (no-match)" **อย่าสื่อสารด้วยสีอย่างเดียว** ให้มีไอคอน (✓ / ✕) หรือข้อความกำกับควบคู่เสมอ

## Type / Spacing / Radius
ใช้ฟอนต์ 2 ตัว แบ่งตามหน้าที่ (ฝังไฟล์จริงไว้ในระบบทั้งคู่ ไม่ได้อ้างอิงจากภายนอก):

| ฟอนต์ | token | ใช้กับ |
|---|---|---|
| **LINE Seed Sans TH** | `--font-sans` | หัวข้อ (display, heading, subheading) และตัวควบคุม: ปุ่ม, Navbar, Badge |
| **IBM Plex Sans Thai Looped** | `--font-body` | ข้อความอ่านและตัวเล็ก: body, caption, คำอธิบายในการ์ด, label/hint/error ของ Field และตัวหนังสือใน input |

ลิงก์ (`.link`) ไม่กำหนดฟอนต์เอง ใช้ตามข้อความรอบข้าง ถ้าเพิ่ม component ใหม่ ให้ถามว่า "นี่คือข้อความที่ผู้ใช้อ่านเป็นประโยค หรือเป็นป้าย/ปุ่ม/หัวข้อ" — ประโยคใช้ `--font-body` ที่เหลือใช้ `--font-sans`

น้ำหนักที่ฝังไว้ตัวละ 2 ระดับ คือ Regular (400) กับ Bold (700) เท่ากัน จึงไม่มี 500/600 ในทั้งสองตัว (LINE Seed จริงๆ มี 5 น้ำหนัก ส่วน Looped มี 7 ถ้าอยากได้น้ำหนักอื่นเพิ่ม แจ้งได้ ต้องเพิ่มไฟล์) ตัวสำรองเรียงตามลำดับ: `--font-body` ตกไป LINE Seed ก่อน (เช่น สัญลักษณ์ ✕ ที่ Looped ไม่มี) แล้วค่อยไป Noto Sans Thai

ส่วน spacing 4 ระดับ, radius 3 ระดับ ยังไม่มีการกำหนดมาจากทีม จึงเป็น scale เริ่มต้นที่ปรับต่อได้ทีหลัง
