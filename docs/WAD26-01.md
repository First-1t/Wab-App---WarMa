# **Part 1 — User Requirements**

# 1\. การสัมภาษณ์ผู้ใช้

ทีมได้ทำการสัมภาษณ์ผู้ที่มีความรู้และเกี่ยวข้องกับปัญหาของโปรเจค เพื่อทำความเข้าใจปัญหาของระบบจำลองการเจริญเติบโตและผลผลิตพืช โดยในปัจจุบันโครงการมุ่งเน้นไปที่ มันสำปะหลัง

* จำนวนผู้สัมภาษณ์: 1 คน  
* บทบาท: อาจารย์คณะเกษตร  
* กลุ่มผู้ใช้เป้าหมายของระบบ: บุคคลทั่วไป โดยเฉพาะเกษตรกร  
* วิธีการสัมภาษณ์: สัมภาษณ์แบบพบหน้า (In-person)  
* หัวข้อ: การจำลองการเจริญเติบโตและผลผลิตของมันสำปะหลัง

แม้ผู้ที่สัมภาษณ์จะไม่ใช่เกษตรกรโดยตรง แต่เป็นผู้ที่มีความรู้และความเข้าใจในด้านการเกษตร รวมถึงปัญหาที่เกี่ยวข้องกับการจำลองผลผลิต ซึ่งสามารถให้ข้อมูลเกี่ยวกับปัญหาและความต้องการของกลุ่มผู้ใช้เป้าหมายได้

## 2\. ผลที่ได้จากการสัมภาษณ์ (Key Findings)

### Finding 1 — โปรแกรมที่ใช้ในปัจจุบันเข้าถึงยากสำหรับผู้ใช้ทั่วไป

ปัจจุบันหากต้องการจำลองการเจริญเติบโตและผลผลิตของพืช สามารถใช้โปรแกรม DSSAT ได้ แต่โปรแกรมมีความซับซ้อนและต้องอาศัยความรู้เฉพาะทาง ทำให้ผู้ใช้ทั่วไป เช่น เกษตรกร สามารถใช้งานได้ยาก

> “ถ้าจะจำลองการโตและจำนวนผลผลิตพืช ตอนนี้ใช้ DSSAT ซึ่งค่อนข้างยากสำหรับคนทั่วไปหรือเกษตรกร”

ผลต่อโครงการ: ระบบใหม่ควรลดความซับซ้อนของการใช้งาน และไม่บังคับให้ผู้ใช้ต้องเข้าใจหรือใช้งาน DSSAT โดยตรง

### Finding 2 — การจำลองแต่ละครั้งใช้เวลานาน

การจำลองด้วยวิธีเดิมใช้เวลาค่อนข้างนานในแต่ละครั้ง ทำให้ไม่สะดวกหากต้องการทดลองหรือเปรียบเทียบหลายสถานการณ์

> “การจำลองแต่ละครั้งใช้เวลานาน”

ผลต่อโครงการ: ระบบควรทำให้ขั้นตอนการจำลองสามารถใช้งานได้สะดวกและรวดเร็วขึ้น เพื่อให้ผู้ใช้สามารถทดลองสถานการณ์ต่าง ๆ ได้ง่ายขึ้น

### Finding 3 — ผลลัพธ์จากระบบเดิมไม่เป็นรูปแบบที่ผู้ใช้ทั่วไปนำไปใช้ได้ง่าย

ผลลัพธ์จากการจำลองเดิมเป็น น้ำหนักแห้ง (Dry Weight) ของพืช ซึ่งอาจไม่ใช่รูปแบบที่เกษตรกรนำไปใช้ในชีวิตจริงได้โดยตรง

สำหรับมันสำปะหลัง เกษตรกรสามารถขุดผลผลิตขึ้นมาแล้วนำไปชั่งเพื่อขาย ซึ่งเป็นลักษณะของ น้ำหนักสด/น้ำหนักเปียกมากกว่า

> “ผลที่ได้เป็นน้ำหนักแห้ง ซึ่งเอาไปใช้จริงค่อนข้างลำบาก เพราะเกษตรกรเวลาขุดมันสำปะหลังขึ้นมาก็ชั่งน้ำหนักแล้วนำไปขาย”

ผลต่อโครงการ: ระบบควรนำเสนอผลลัพธ์ในรูปแบบที่เข้าใจง่ายและใกล้เคียงกับการใช้งานจริง โดยเฉพาะน้ำหนักสด/น้ำหนักเปียกของมันสำปะหลัง

### Finding 4 — ไม่จำเป็นต้องให้ผู้ใช้กรอก Input ทุกตัวของการจำลอง

ก่อนการสัมภาษณ์ ทีมมีแนวคิดว่าจะให้ผู้ใช้กรอกข้อมูลจำนวนมาก เช่น พันธุ์พืช การให้น้ำ วันปลูก ปริมาณปุ๋ยไนโตรเจน ระยะห่างระหว่างการปลูก และข้อมูลอื่น ๆ

อย่างไรก็ตาม จากการสัมภาษณ์พบว่า Input บางตัวไม่ได้ทำให้เห็นความแตกต่างของผลลัพธ์อย่างชัดเจน เช่น ปุ๋ยไนโตรเจนและระยะห่างระหว่างการปลูก

ดังนั้น การมี Input จำนวนมากไม่ได้หมายความว่าจะทำให้ระบบมีประโยชน์มากขึ้นเสมอไป

ผลต่อโครงการ: ทีมจะลดจำนวน Input ที่ผู้ใช้ต้องกรอก และเลือกเฉพาะ Input ที่มีผลต่อผลลัพธ์อย่างชัดเจนและผู้ใช้สามารถเข้าใจได้ง่าย

## 3\. สิ่งที่เปลี่ยนแปลงหลังการสัมภาษณ์

จากเดิมทีมมีแนวคิดที่จะสร้างระบบที่ให้ผู้ใช้กรอก Input จำนวนมากเพื่อให้สามารถกำหนดรายละเอียดของการจำลองได้มากที่สุด

หลังจากสัมภาษณ์ ทีมพบว่าการให้ผู้ใช้กรอกข้อมูลจำนวนมากอาจทำให้ระบบ ซับซ้อนเกินความจำเป็น โดยเฉพาะสำหรับกลุ่มเป้าหมายที่เป็นผู้ใช้ทั่วไปหรือเกษตรกร

ดังนั้น ทีมจึงปรับแนวคิดเป็น

ลด Input ที่ไม่จำเป็น → จำลองสถานการณ์ → แสดงผลลัพธ์ที่เข้าใจง่ายและนำไปใช้ได้จริง

โดยในระยะปัจจุบันจะเน้นที่ มันสำปะหลัง เป็นหลัก
